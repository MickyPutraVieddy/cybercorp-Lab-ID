5. EXACT MANUAL TESTS (do in the LAB Supabase project + a Vercel Preview or `pnpm dev`)
 SETUP
 1. pnpm add @supabase/supabase-js @supabase/ssr server-only ; pnpm install ; pnpm typecheck ; pnpm lint ; pnpm build. Record results.
 2. Create Supabase project `lets-test-it-lab`. Authentication > Providers: Email ON, "Confirm email" ON, all others OFF.
    Authentication > Policies/Password: minimum length 10.
 3. URL Configuration: Site URL = your URL (http://localhost:3000 or Vercel preview); Redirect URLs add <site>/auth/callback.
 4. (Recommended) Authentication > Email Templates: Confirm signup link ->
      {{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&type=signup&next=/dashboard
    Reset password link ->
      {{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&type=recovery
 5. Read, then run in SQL editor (lab only): 0001 then 0002. Run `select * from public.user_roles;` (empty/only 'user' rows).
 6. Set env vars (.env.local / Vercel): NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY,
    NEXT_PUBLIC_SITE_URL, APP_ENV=lab, SECURITY_IP_HASH_SALT. Leave SUPABASE_OWNER_USER_ID empty for now.
 AUTH
 T1 Register with a new email + strong password + terms. Expect "check your email" message. Check DB: profiles + user_roles row, role='user'.
 T2 Try to log in BEFORE confirming. Expect "confirm your email first".
 T3 Open the email link. Expect landing on /dashboard?notice=confirmed (same browser) and logged in.
 T4 Register again with the SAME email. Expect the same neutral message (no "already registered").
 T5 Register with password "short", mismatched confirm, no terms. Expect each validation message.
 T6 Log in with wrong password. Expect "Invalid email or password"; log in correctly -> /dashboard. Header shows Dashboard/Log out.
 T7 Reload, close/reopen tab: session persists. Log out: header returns to Log in/Register; /dashboard redirects to /login?next=/dashboard.
 T8 Forgot password: submit your email -> neutral message; open link -> /reset-password; set new strong password -> /dashboard?notice=password-updated;
    log in with new password. Submit a non-existent email -> identical neutral message.
 T9 Open /reset-password while logged out -> redirected to /forgot-password with "invalid or expired".
 T10 Dashboard: edit full name (saved); change password with wrong current password (rejected) and right one (accepted).
 T11 /login?next=https://evil.example and /login?next=//evil.example -> after login you land on /dashboard, never off-site.
 OWNER / RBAC
 T12 Copy your own user UUID (Authentication > Users) into SUPABASE_OWNER_USER_ID, redeploy/restart. Log in as that user.
     Expect redirect to /admin and role Owner. SQL: select * from public.user_roles where role='owner'; (exactly 1 row);
     select * from public.audit_logs order by created_at desc; (shows role_assigned for owner).
 T13 Restart/reload several times: no duplicate audit rows (idempotent).
 T14 Register + confirm a second account B. B visits /admin -> redirected to /dashboard?notice=forbidden.
 T15 As owner, /admin/users: promote B to admin. Audit page shows role_changed with actor=owner. Log in as B: /admin works,
     Users visible, but no "Change role" controls; /admin/audit redirects (admin lacks audit.read).
 T16 As owner promote B to super_admin, register account C. As B: C can be set user<->admin; B cannot see controls for the owner
     or for itself; no super_admin option offered.
 T17 Direct attack attempts (should ALL fail), run in SQL editor as role `authenticated` or via supabase-js with B's session:
     update public.user_roles set role='owner' where user_id=<B>;  -> permission denied / RLS.
     update public.user_roles set role='admin' where user_id=<B>;  -> denied (no UPDATE privilege).
     select * from public.audit_logs; as a plain user -> 0 rows.   delete from public.audit_logs; -> denied.
 T18 Try to forge a request: in browser devtools replay the role-change server action as account C (plain user) -> "forbidden".
 T19 Service role: confirm the key string never appears in browser: view-source / Network tab / `grep -r service_role .next/static`
     (or run `pnpm check:public-build` after build).
 T20 Security headers: `curl -sI <site>/login` -> X-Frame-Options DENY, CSP frame-ancestors 'none', Cache-Control no-store;
     `curl -sI <site>/` -> nosniff, Referrer-Policy, HSTS, Permissions-Policy.
