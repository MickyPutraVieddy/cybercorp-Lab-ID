Date: 2026-11-13
Scope: UI/flow change on top of Phase 3. No new dependencies. No migration applied (0003 is PROPOSED only).

1. WHAT CHANGED (user request)
 a) First page (/) is now an introduction page with the login / register forms next to it. The store is behind login.
    After a successful login the user lands on /home (store home: catalog, bag, checkout preview).
 b) Design follows the existing Let's Test It look (forest green, cream paper, clay accent, Georgia headings). Intro layout is
    a hero (badge, headline, lead, CTA, stats strip) + auth card on the campaign artwork, then About / How it works / Roles.
 c) Header (store pages):
      - Guest: PROFILE icon + "Log in" label. Tooltip: "Profile icon — click here to log in".
      - Signed in: SETTINGS icon + role chip (Member / Admin / Super admin / Owner). Tooltip: "Settings — your role: <role>".
      - owner / super_admin / admin: extra "ADMIN DASHBOARD" button (tooltip: "Click here to open the Admin Dashboard") -> /admin.
      - Log out icon. On phones the icons stay in the header, text labels are in the mobile menu.
 d) /settings (new, e-commerce style "My account"): avatar + name + @username + email, role pill + description of what that role
    can do, Admin Dashboard button for staff, shortcuts (store, bag, order tracking), edit username / full name / phone,
    shipping address, language + currency preferences, change password, log out.
 e) /admin layout got "Back to store" and "My settings" links.

2. ROUTING / ACCESS RULES
 - PUBLIC: /  (intro + login/register), /login & /register (redirect to /?mode=...), /forgot-password, /reset-password,
           /about /help /contact /privacy /terms /careers, /auth/callback, /api/me.
 - NEEDS LOGIN (proxy.ts gate, then server-side again): /home /catalog /products/* /cart /checkout /order-confirmation
           /order-tracking /settings /dashboard /admin/*.
 - Not logged in -> redirect to /?mode=login&next=<path>. After login -> <next> (same-site paths only) or /home.
 - Logged in visiting / -> redirect to /home.
 - /dashboard -> redirect to /settings (old links keep working). Email confirmation now lands on /home?notice=confirmed.
 - homeForRole() now returns /home for every role (staff used to land on /admin; they now use the Admin Dashboard button).
 - FAIL-CLOSED: if Supabase env vars are missing, the store pages redirect to the intro page, which shows
   "Authentication is not configured". Configure Supabase (docs/11 section 5) before the store can be opened.
 - / and /settings now send X-Frame-Options DENY, frame-ancestors 'none', Cache-Control no-store (next.config.mjs).

3. NEW MIGRATION (PROPOSED, NOT APPLIED): supabase/proposed-migrations/0003_profile_settings.sql

 - public.profile_details (phone, address, city, province, postal code) with owner-only RLS and NO staff policy:
   admins cannot read members' phone/address (privacy by design; profiles has a staff-read policy, so these fields were NOT put there).
 - Column grant: authenticated may update (full_name, username) on profiles only.
 - Without 0003 the settings page still works for name + password; username/address save shows "not available yet".
 - Run order in the LAB project: 0001, 0002, then 0003. Read it first.
